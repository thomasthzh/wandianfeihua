# 当前 macOS 基线与集群 Web OS 进展

记录日期：2026-10-19。本文将桌面体验、真实后端、部署状态与最终业务验收分别说明。应用源码、构建产物和私有发布工具仍不属于本仓库的公开内容。

## 当前参考版本已核实

Apple 的[安全发布页面](https://support.apple.com/en-us/100100)将最新 macOS 列为 **27.0.1**；[开发者正式发布记录](https://developer.apple.com/news/releases/?id=09282026c)列出其发布日期为 2026-09-28。[产品页面](https://www.apple.com/os/macos/)使用 **macOS 27 Golden Gate** 名称，并强调玻璃材质可读性、工具栏和窗口一致性。这里按记录日核实版本，不把较早的 Tahoe 模拟器直接称为当前最新版。

参考最新 macOS，意味着认真研究窗口、应用切换、工作区、菜单、搜索和无障碍等使用方式；不只是给网页加一层透明背景。Apple 的 [Spaces 指南](https://support.apple.com/guide/mac-help/work-in-multiple-spaces-mh14112/mac)可作为工作区组织的参考。具体交互转化为网页能力，仍是本项目自己的设计与实现。

「万点飞花」是集群上的浏览器工作环境。它不会因采用相似窗口外观而获得 macOS 内核、驱动、原生软件或硬件控制能力，也不宣称所有视觉效果与系统功能已经复刻完成。

## 本轮窗口总览解决了什么

桌面原有可拖动、缩放、并排、最小化和恢复的窗口，以及 Dock、应用图标、搜索和布局保存。早期“窗口”入口只是一张列表。新候选将它扩展为实际使用已开窗口状态的总览：

- 通过菜单进入，也提供网页快捷键；快捷键是否收到，取决于浏览器和系统拦截规则。
- 按最近使用排列，搜索应用名称与描述，筛选全部、正在桌面或已最小化窗口。
- 卡片可以切换、恢复、最小化和关闭窗口；方向键、Home/End、Enter 和 Escape 可操作。
- 进入后约束键盘焦点，退出时恢复焦点；选择应用后聚焦实际窗口。
- 原应用页面保持原有挂载，不为总览创建第二份 iframe，也不因最小化而销毁业务页面。
- 缩略内容明确标注为“窗口示意”，没有冒充跨来源页面的实时截图。
- 小屏采用紧凑布局，并响应减少动画与减少透明度偏好。

隔离浏览器先验证了总览搜索、最小化、方向键加 Enter 恢复及实际窗口焦点；随后本人公网会话也完成总览搜索、键盘恢复实际焦点和两个窗口左右并排验证。桌面交互可用仍不能代替每个原应用的业务验收。

## 受限真实运行时

本次发布已将部分系统工具从演示数据接到生产受限后端。范围刻意明确：

| 能力 | 候选实际实现 | 仍未提供 |
| --- | --- | --- |
| 核心节点 | Linux CPU 差值、内存与应用数据卷使用率，标注采样来源和时间 | 节点维护、重启、任意远程命令 |
| Tailnet 节点 | 固定只读状态命令返回的在线情况 | 远端 CPU、内存、磁盘采集；这些字段显示未知 |
| 文件 | 服务专属数据根下 files 子目录的列举、创建、编辑、上传和下载 | 系统目录、身份文件、其他节点目录、任意挂载及删除 |
| 任务 | 应用目录元数据扫描、已观测节点状态检查，排队、取消、日志与恢复 | restart、backup、transfer、shell 或浏览器提供的任意命令 |
| 持久状态 | 与本地演示账户分开的任务、审计和显示偏好 | 读取生产账户秘密或将演示节点灌入真实状态 |

资源未知时显示“—”。CPU 首次采样需要等待下一次有效差值；Tailnet 在线状态不代表已经测量了远端资源，也不代表 HTTP 业务可用。

文件按一个明确授权根限制路径，拒绝穿越、符号链接、硬链接与特殊文件；单文件上限 **5 MiB**。写入使用同目录临时文件替换。该目录由服务独占，不能把它同时交给不可信的本地写入者，再宣称路径检查形成了内核级隔离。

任务队列单次只运行一个作业，最多 **8** 个活动任务，执行时限 **15 秒**。目录扫描限制 **5,000** 个条目和 **32** 层，不读取文件内容。节点检查只使用固定来源，不扫描端口。已运行但被服务重启中断的任务标为失败，原有排队任务按固定类型恢复。

这些能力继续使用既有 owner 会话、Origin 与 CSRF 校验，没有增加“为了测试方便”的生产登录旁路。终端、跨节点文件和管理动作仍是后续独立任务。

本人公网会话已核对实际核心指标与 Tailnet 状态；授权目录文件的创建、编辑，以及关闭编辑器、刷新后重新读取均通过。真实目录扫描的统计与测试内容一致，浏览器刷新后任务仍保留。这里只公开测试方法与结论，不记录测试文件、实际大小、节点数量或任务标识。上传下载、任务取消、probe 和服务重启恢复仍待生产验收。

## “任务执行完了”不等于“结果保存成功”

独立审查发现过一个实际缺陷：任务操作已结束，内存先标成成功，最终状态写盘失败后，页面仍可能继续报告成功。

修复后的规则是：最终结果持久化失败，任务不能保留成功状态；移除该任务的成功审计，追加固定安全错误说明，暂停队列并拒绝新任务。已经取消的任务保持取消，不被错误改成成功或覆盖成其他状态。只做一次有界的降级状态保存，不进入自动重试循环。

回归使用真实临时文件系统制造原子替换失败，而不是把保存函数简单改成抛错。测试也先完成一条相同目标的任务，确认只移除故障任务的成功事件，已有可信历史保持。界面显示存储错误，修复存储后再重启恢复处理。

这条经验适用于整个 Web OS：操作完成、状态落盘、审计记录和用户看到的结果，应形成一致的提交语义。

## 把发布整理成一次本人提权执行

此前多个准备工具分别正确，却让本人反复往返终端、复制命令和收集通用失败码。新候选将同一发布阶段收敛为一次本人执行的入口，内部仍保留分阶段检查和回退。

| 顺序 | 工具应做的事 | 操作者应能确认的结果 |
| --- | --- | --- |
| 1 | 校验固定候选、公开输入与已有受管文件 | 来源和范围明确，未知内容不覆盖 |
| 2 | 复用已有身份、证书与私有配置，现场复核动态地址 | 不重复初始化、不重新收取秘密 |
| 3 | 检查所选版本的后端、证书、身份服务与网关 | 具体组件和安全分类，未知错误不外显原文 |
| 4 | 选择发行版本，按身份入口、网关、BFF 依赖激活 | 不用进程 active 代替 HTTP 或 OIDC 就绪 |
| 5 | 按已批准范围处理入口与 DNS，验证旧业务 | 差异可核对，失败可停止或回退 |
| 6 | 汇总已完成与待验收项 | 基础设施、本人正向登录、负向认证与应用业务分别记录 |

一次执行不代表无限授权，也不表示失败时不断循环。需要本人输入的密码、动态码、条款接受或新凭据，仍由本人在相应受控流程完成。公开手册没有附带这个私有工具，不能据此复制一条不存在的“一键安装命令”。

首轮单入口在 BFF 校验处停止，没有执行后续激活。恢复入口将固定环境分类、已知输入修正和完整重校验合并；本人实际恢复时环境已规范、无需修改，四阶段通过后才完成了后续核心与 DNS 激活。引号形式可合成复现同类错误，但仍不能当作现场根因，详见 [NODE_ENV 排错](05-troubleshooting.md#bff-曾拒绝-node_env恢复时未修改现场变量)。
