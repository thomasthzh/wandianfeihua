# 从外观选项走到连续的桌面操作

**状态：本轮已发布，主人密码加 Authenticator 解锁、默认在线监控视图及头像保存刷新已通过公网验收。** 原生监控默认选中在线项，真实读数持续变化，完整资产仍保留；内置头像保存后整页刷新仍能读取，并已验证恢复默认。现场版本与服务运行态、匿名认证跳转、可信 TLS、解锁页仅语言入口分别保留证据。本地照片上传、菜单键盘操作、图标操作和部分设置的证据单独保留；硬件多触点与窄屏实测仍未完成。

本章记录六项相互关联的改进：监控默认显示在线设备、登录页只保留语言入口、菜单栏与程序坞的材质和键盘操作、个人头像、可操作的系统设置，以及桌面图标的自由摆放和多选。文中的角色、地址和示例均为脱敏说明；本仓库仍是实践手册，不包含可直接启动的完整发行包。

## 先为每项需求确定可观察的结果

| 需求 | 本轮实现 | 当前证据与后续检查 |
| --- | --- | --- |
| 默认显示在线设备 | 在受核验的原生监控版本中调整初始状态筛选，保留原生“全部”等选项 | 公网默认在线项已选中，其他筛选未选，真实读数持续变化；完整资产保留，不以视图过滤修改原记录 |
| 登录页只保留语言入口 | 本人已确认范围是登录解锁页；从认证页组件中移除账号设置入口，保留语言选择和原认证流程 | 隔离组件检查与构建通过；公网仅语言入口、匿名边界、可信 TLS 以及本人密码加动态码解锁均通过 |
| 菜单与程序坞 | 分层玻璃材质、运行反馈、键盘菜单和焦点交接 | 本地菜单方向键与 Escape 返回触发按钮通过；降低透明度可实际关闭程序坞模糊并恢复，减少动态效果状态生效；窄屏仍待验收 |
| 个人头像 | 内置头像、颜色文字头像、照片上传与服务端个人资料保存 | 公网内置头像保存、整页刷新读取和恢复默认通过；本地实际上传 PNG，经压缩后保存、加载为 256 × 256；跨设备重新读取仍待验收 |
| 系统设置 | 搜索、通用、真实网络、菜单栏及辅助功能均连接实际状态或动作 | 本地时钟与搜索入口隐藏、恢复通过；从文件搜索切入设置再经程序坞返回，原内容保留；网络投影与偏好检查通过，分类滚动已有针对性修正 |
| 桌面图标操作 | 自由坐标、框选、多选移动、键盘选择和浏览器持久化 | 本地单拖持久化、多选移动、Escape 取消、实际框选和右键整理通过；硬件多触点与窄屏仍待验收 |

这里的“在线”来自监控应用本身的状态，网络成员列表来自 Tailnet 运行时。两类来源应分别标示；不能用网络在线代替资源采样，也不能把未知资源画成零。

本轮发布器先核对制品和同一服务账号下的候选配置，再启用桌面与身份组件。发布后独立查询当前版本与服务运行态，并从匿名浏览器检查桌面认证跳转、解锁页和可信 TLS；随后本人完成密码加动态码解锁，真实会话中确认默认在线监控与头像保存刷新。其他项目回归、退出重登与长期连接继续分别验收，不用匿名页面或单一功能结果代替。

## 默认在线视图仍保留完整资产清单

监控首页更适合先呈现当前在线的设备，让使用者打开窗口就能看到正在更新的内容。离线资产和暂停资产仍留在原生数据库，用户可以从原生筛选菜单切回完整视图。

本次沿用原生表格的筛选、分页、排序与实时更新，只在固定上游版本被核验后改变初始状态。版本或资源结构发生变化时，适配器应拒绝继续转换，等待重新审查。对压缩脚本进行宽泛的字符串替换，容易在上游升级后改错位置。

验收应覆盖首次进入、用户切换筛选、实时状态变化及再次打开窗口。列表更短只说明视图筛选生效；资产完整性还要通过“全部”视图核对。这个改动不应发送创建、删除或状态修改请求。

## 让登录页专心完成解锁

认证页的公共工具区仅保留语言入口。桌面偏好和个人资料放在解锁后的系统设置中，密码与 Authenticator 验证继续由既有身份服务处理。

移除入口时，需要确认组件实际不再挂载，而不只是用样式藏住按钮。否则隐藏菜单仍可能进入键盘顺序，或在其他状态下重新出现。补丁和测试应针对固定身份组件版本，重新编译制品后再验证真实登录路径。本轮发布后已在浏览器看到工具区仅保留语言入口，本人密码加动态码解锁也已通过；本轮退出重登仍单独待验收。

个人照片只从已认证的个人资料接口读取。公共解锁页继续使用公共素材；不会为了显示私人头像而增加匿名个人资料接口。语言、密码输入、动态码输入、错误提示和原有验证规则均需保留可操作性。

## 玻璃材质需要同时照顾内容与操作

菜单栏、弹出菜单、控制中心与程序坞处在不同的视觉层。工具层可以透出壁纸，菜单需要足够稳定的底色，正文区域则保留清楚的内容背景。背景模糊、边缘高光和阴影分别承担层次作用，不必给所有内容叠加同样的效果。

程序坞以图标的静止槽位计算指针距离，先统一读取位置，再更新变换，减少逐项读写布局造成的抖动。运行、启动、最小化恢复反馈与真实窗口状态连接，减少动态效果时则收敛动画。浏览器端的这些材料与动效仍需按实际壁纸、主题和设备核对；原生 GPU 折射和宿主全局按键属于不同的能力边界。

键盘验收也属于材质改进的一部分：

- 菜单触发按钮可通过键盘打开；方向键在菜单及菜单栏之间移动。
- Escape 关闭弹层并回到触发按钮，Tab 能继续离开弹层。
- 控制中心的滑块保留自己的方向键操作。
- 程序坞支持方向键、首尾导航与可见焦点。
- 隐藏菜单栏项目后，系统设置仍有可达入口，相应功能和既有快捷键继续保留。

增强对比度、降低透明度、系统无障碍偏好与强制颜色模式需要在深浅主题上分别检查，避免后置的主题规则覆盖无障碍规则。

## 个人头像作为账号资料保存

头像操作包含内置图案、颜色文字头像、照片上传和恢复默认。显示名称结束编辑后更新，头像选取后更新；两者通过受保护的个人资料接口保存，并由接口响应更新桌面状态。

上传流程保持有限：

1. 客户端只接受 PNG、JPEG、WebP，检查输入大小及文件内容签名。
2. 解码后按图片中心取正方形，再缩放到有限尺寸。
3. 重新生成 PNG，限制最终字节数；处理结束释放解码图片。
4. 服务端再次验证 PNG、尺寸、体积、名称和当前身份，只更新当前主人的资料。
5. 请求成功后显示新头像，失败时显示可理解的错误，保留可重试的编辑内容。

照片显示为圆形，实际保存的是有限尺寸的正方形 PNG。原始上传文件、外部图片链接和 SVG 不作为头像资料直接存入。姓名与头像的更新不应修改密码、验证器绑定、钥匙串或已有应用身份。

名称输入转向头像选项时，可以合并提交尚未保存的名称和新头像，避免先触发名称保存，随即把用户刚点击的头像动作丢掉。

## 系统设置的每一行都需要真实来源或动作

侧栏采用可搜索的分类。搜索结果能直接进入对应面板，窄窗口中仍保留个人资料入口。外观和墙纸在选择后提交，不再要求额外寻找“保存更改”；服务器拒绝时恢复原选择，服务器已保存但状态刷新失败时则明确说明两者的区别。

通用面板展示 Web OS 自身版本、核心系统、实际可得的处理器和内存摘要，并连接节点管理、应用数据文件与任务中心。应用数据卷使用率需要标明范围，不能据此声称已完成整个集群的储存管理。

网络面板同时展示配置角色和实际运行状态。例如，一套示例拓扑可以写为：

```text
公网 IPv4 → edge.example.invalid
公网 IPv6 → core.example.invalid
核心工作空间 ↔ Tailnet 成员
```

上述箭头表示配置关系。节点卡片从真实运行时投影，点击后显示该节点的地址、系统、来源和采样情况；未知资源显示“未采集”，离线状态清楚标示。尚未测试的直连链路、延迟或带宽不补造数值。

菜单栏面板保存网络状态、时钟、搜索、控制中心和台前调度的显示偏好。辅助功能面板连接减少动态效果、降低透明度、增强对比度和界面文字大小；这些设置应实际改变界面。嵌入项目的字号仍由原项目管理，不向跨来源页面强行注入样式。

### 这轮实际遇到的两个连续性问题

第一个问题出现在即时保存：点击外观按钮后，处理中状态立即把按钮设为原生禁用，浏览器随即移走焦点。修正后，处理中按钮保留焦点，通过同步忙碌状态阻止重复提交，并标明不可重复操作。请求结束后不会无条件调用聚焦，以免把已移动到另一控件的用户拉回旧按钮。名称输入在提交期间保持只读。

第二个问题是长页面的滚动位置被沿用到下一分类，导致新面板标题一开始就被卷出。分类切换和进入或离开搜索结果时重置内容区滚动；头像保存、主题更新或后台状态刷新则保持原滚动位置。

保存后保留焦点已在内置头像操作中实际确认。分类滚动修正仍需随最终候选继续回归。类型检查和数据模型测试无法单独证明全部焦点与滚动行为。

## 桌面图标从排序改为自由布局

每个图标保存独立坐标。初次排列提供整齐的起点，后续拖动保留用户位置；框选、修饰键选择和整组移动共同维护选择集合。移动多项时，整组统一约束在桌面范围内，以保留项间距离。

指针拖动与点击分开处理：超过阈值后进入拖动，抬起时提交位置；取消则恢复起点。拖动结束要抑制紧随其后的点击，避免移动图标却意外打开应用。窗口尺寸变化后，将坐标约束回可见区域；损坏的浏览器存储不会直接成为有效坐标。

键盘操作使用实际图标位置寻找方向上的相邻项。Enter 可以打开项目，修饰键支持扩展选择；“整理图标”和“按名称整理”提供明确的重新排列操作。图标坐标、应用排序与窗口几何分别管理，移动桌面图标不重建正在运行的项目 iframe。

## 分清哪些设置会随账号同步

| 数据 | 本轮保存位置和范围 |
| --- | --- |
| 显示名称、头像 | 受认证保护的主人资料，支持其他设备重新读取 |
| 主题、墙纸 | 工作空间后端设置 |
| 菜单栏、文字大小、对比度及桌面效果 | 当前浏览器的显示偏好 |
| 图标位置与选择操作 | 位置保存在当前浏览器；临时选择留在当前桌面状态 |
| 项目原生会话与秘密 | 沿用服务端钥匙串及原有授权边界 |

本地持久化成功不代表跨设备同步。清除浏览器数据与重新登录，也需要按保存范围判断预期结果。

## 从本地候选走到公网验收

先完成类型、构建、输入边界及几何检查，再用真实鼠标和键盘检查操作。最后的候选应连同桌面、后端与认证制品核对来源，检查配置后发布；既有密码、Authenticator 和项目身份材料沿用，不因外观升级重新初始化。

下面的顺序既用于已列出的本地检查，也用于后续公网复核；没有实际结果的项目继续保留为待验收：

1. 首次进入监控显示在线项，切到全部后仍能看到原有资产。
2. 公共登录工具区仅显示语言入口，密码加动态码仍能正常解锁。
3. 深浅主题、不同壁纸与无障碍模式下，菜单和程序坞均可读、可操作。
4. 用键盘打开菜单、调整滑块、退出弹层和移动程序坞焦点。
5. 保存内置头像、上传照片、恢复默认并重新读取；确认保存完成后焦点没有丢失或被抢回。
6. 搜索设置、切换长短面板、操作节点详情，验证内容区滚动及未知数据说明。
7. 隐藏菜单栏项目、调整文字与对比度，确认即时生效且系统设置仍可进入。
8. 单项和多项拖动图标，检查框选、取消、边界、重新载入及整理操作。
9. 回到原有真实项目，检查窗口、搜索、iframe 连续性与会话；长期连接、锁定和退出单独计证据。

公开记录保留每项的实际结果和未完成范围。公网入口可访问、候选构建成功或某个按钮保存成功，都不能代替整轮桌面体验验收。窗口与台前调度的既有流程见[上一轮交互与监控实践](14-stage-manager-and-native-metrics.md)，后续工作空间候选见[从窗口门户走向有连续状态的 Web OS](17-from-windows-to-workspace-os.md)，公开更新方法见[文档公开与更新流程](06-publication-process.md)。
