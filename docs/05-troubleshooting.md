# 故障手册：保留证据，再缩小问题

本文重写实施中实际遇到的问题，不包含现场日志、账户、地址、证书或秘密。示例桌面域名为 `os.example.net`，身份域名为 `auth.os.example.net`。以下经验用于定位问题，不能替代目标环境的验证。

## 页面漂亮，却不像虚拟电脑

**现象：** 页面有很多卡片、指标和节点状态，用户仍认为它不符合要求。

**原因：** 需求被过早翻译成了仪表盘，缺少应用启动、多窗口工作和返回原任务的操作路径。

**处理：** 先演示一个具体流程：登录、打开两个真实项目、调整窗口、切换焦点、最小化与恢复，再讨论视觉细节。监控是桌面里的一个应用，不应替代桌面本身。设计验收应记录用户能完成的动作。

## HTTP 200，但打开的不是管理应用

**现象：** 探测成功，窗口内却是提示页、健康页、默认页或登录页，实际管理功能不可用。

**处理：** 核对最终 URL、页面身份、重定向、资源请求与浏览器里的真实交互。将“服务响应”“登录页可打开”“已完成授权管理”分开记录。不要为了消除失败状态而把一个返回成功的地址随意登记成应用入口。

## 面板能登录，终端或文件传输失败

**本次例子：** MCSManager 的面板显示正常，不代表浏览器到 daemon 的链路已经完成。

**处理：** 检查应用在浏览器中实际使用的第二来源、HTTPS/WebSocket、地址映射和文件传输请求。候选同来源分流必须使用固定路径和固定上游，保留 daemon 的原有认证。最终以经过原管理员授权的终端操作、上传和下载验证，不能只看登录页。

## iframe 空白或反复跳转

**可能原因：** 原站限制嵌入、Cookie 不适用于当前上下文、身份跳转要求顶层页面，或原站仍需要自己的登录。

**处理：** 在浏览器中检查嵌入策略和重定向链，确定原应用支持的集成方式。`frame-ancestors` 控制哪些父页面可以嵌入当前页面；不能把粗暴删除原站保护头当成通用修复。[MDN：frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors)

身份门户使用顶层登录流程。对不适合嵌入的应用，应明确呈现其限制和受支持的打开方式，不能为了保留一个窗口外观而牺牲原站身份边界。

## Windows 找到了两个 SSH 程序

**本次原因：** PowerShell 5.1 的 `Get-Command` 返回了多个 Application 结果，直接取 `.Source` 得到数组，后续调用把多个路径当成了一个命令。

**修复：** 显式选择一个应用程序结果，再检查得到的调用路径。多候选是环境事实，不能假设每台电脑都只有系统自带 SSH。[Microsoft：Get-Command](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/get-command?view=powershell-5.1)

```powershell
$sshPath = Get-Command ssh -CommandType Application |
    Select-Object -First 1 -ExpandProperty Source
```

调用前先运行只读预检，验证程序解析和公开来源核对；只有显式进入迁移阶段后才读取本人账号材料。预检成功不能被描述成身份迁移已完成。

## TTY 上的隐藏输入还没开始就退出

**本次原因：** Python 在真实 PTY 上以 `r+` 模式打开终端，触发了 `UnsupportedOperation`。早期测试替换了终端对象，绕过了实际流行为。

**修复：** 为终端输入与提示输出使用独立的读、写句柄；隐藏输入无法保证时停止，不退回会回显的普通输入。回归测试必须在隔离的真实 PTY 中执行实际实现，验证提示、输入顺序、隐藏效果和退出路径。Python 的流接口区分可读、可写与可 seek 能力，文件模式名称不能保证终端具备普通文件的所有操作。[Python I/O 文档](https://docs.python.org/3/library/io.html)

## ACME 返回 503 或 rateLimited

**不要直接下结论：** 这不等于 Token 错误，也不证明一定触发了某一种请求额度。应保留最后相关 ACME 响应及其阶段，在本机把协议类型和状态转换成安全分类。

**处理：** 核对 `Retry-After`，到期之前不发起新的尝试。保留已有专用账号和凭据，采用一次明确授权的恢复，避免无限重试或删除配置重新初始化。官方说明总请求限制可能返回 503，并通过该响应头指示等待时间。[Let’s Encrypt 限流说明](https://letsencrypt.org/docs/rate-limits/)

没有可用响应头时，本地的保守等待策略只是恢复保护措施，不能当作 CA 保证。也不能因为旧日志出现过协议错误，就认定它是本次终止原因；一次错误后可能已经有成功响应。

## 新增桌面记录后，其他应用解析改变

**原因：** DNS 通配不是所有名称都永久回落到同一个地址。建立精确的 `os` 节点会改变最近匹配范围，先前继承上层通配的应用子域可能失去原来的结果。空非终端的处理还可能随解析服务类型而不同。[Cloudflare：通配记录](https://developers.cloudflare.com/dns/manage-dns-records/reference/wildcard-dns-records/)

**处理：** 对拟选择和未选择的应用都做解析影响分析，必要时查询权威结果。精确名称存在 CNAME、多条同类型记录、未知类型或委派时停止自动建议，先核对归属。不要为了使桌面解析正确而盲目删除其他记录。

证书里使用通配域名，与 DNS 控制面是否存在通配记录是两件事。IPv6 地址变化也需要同时核对 AAAA、网关绑定和实际入站连通性。

## 别处验证过的 Caddy 配置，在目标机器失败

**本次原因：** 验证使用了另一台机器较新的 Caddy，而新 Web OS 的独立可执行文件实际是 2.6.2，不能接受所使用的代理信任配置。

**修复：** 只升级新系统的独立文件至经过来源核对的 2.11.7，先确认旧文件与受控备份，使用同目录替换并在失败时恢复。不要顺带替换既有应用的网关程序。随后在目标机器上，以实际服务账户和配置重做验证。

今后每个节点都应记录实际版本、模块与检查结果；配置模板与二进制版本一起评审，避免“另一台机器能解析”掩盖现场差异。

## 通用失败过于安全，也过于难用

**现象：** 工具没有泄露秘密，但只返回一条通用失败，用户不知道接下来需要修什么，于是不断往返终端和聊天。

**改进：** 把生产后端、公开证书、Authelia 和网关分开执行，输出阶段状态与有限的已知信号。原始输出留在本机内存，不转发环境值、完整异常或渲染配置。配置失败、输入文件不合格和超时应当可区分；未知错误只返回固定的拒绝状态，不能把任意错误文本拼进结果。

本次通过目标机的版本核对与合成对照定位了版本问题，再用分阶段检查确认升级后四个组件均通过。这个结果仍表述为校验通过，没有把它写成公网发布完成。

## 退出后旧窗口或长连接仍可用

**边界：** 平台会话、身份门户会话、原应用会话，以及已经建立的 WebSocket/SSE 连接，具有不同的生命周期。

**处理：** 分别验证平台退出、门户退出、原站退出、会话过期、禁用身份以及连接重新建立。固定连接时长可以限制部分持续时间，但不能被称为立即撤销所有应用权限。仍未完成的链路应明确标记，不能用统一的“已全部退出”提示掩盖它。

## 减少故障处理本身的往返

对已经稳定的准备工作，应形成一个本人执行的入口：先检查程序与来源，再准备受控文件，随后逐阶段验证并汇总结果。已有正确状态保持不动，未知状态保留并拒绝覆盖；可继续的独立检查一次做完。

同一次入口需要清楚区分“检查”“有限准备写入”和“启用”。已填写且不匹配的配置不能自动改，写入或持久化失败必须回退，回退结果不确定时停止。用户不应为了拿到下一条定位信息，反复重建身份、重签证书或重新输入秘密。

文件、任务与节点管理还需要真实后端、授权和审计。故障记录与页面演示都不能替代这些尚未完成的能力。
