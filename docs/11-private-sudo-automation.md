# 减少重复提权：本机私密凭据与固定 sudo 动作

记录日期：2026-10-19。此前发布由操作者在服务器终端亲自执行合并入口。随着升级和修正增多，复制命令、等待结果、再粘贴下一条成为明显负担。操作者现已明确授权：后续可通过 SSH 自动执行项目所需的 sudo 动作，并愿意在私密窗口输入一次现有密码。

本文公开这次流程改进的设计、验证和边界，不发布私有工具源码、生产执行命令、地址、个人路径、凭据或其密文。**工具候选与独立测试已完成；本人真实凭据登记及随后自动调用尚未完成。** 不能把合成测试写成已经使用真实密码完成部署。

## 操作者只需亲自完成一次登记

登记在本机独立交互窗口中进行，密码输入隐藏，不发送到聊天。工具先通过固定 SSH 入口执行新的 sudo 验证和只读服务检查，成功后才保存凭据，并重新解密、逐字符核对保存值。仅在识别到明确密码拒绝时允许至多三次重新隐藏输入；连接、权限、文件或结果未知等问题直接停止。

后续调用从本机专用目录加载加密凭据，执行有限项目动作。重新登记仍先验证再替换；更换服务器密码后，需要再次登记新值。这里保存的是服务器提权凭据，桌面的密码＋Authenticator、原应用钥匙串和公网身份边界各自沿用原有流程。

## 首次真实登记的完成状态需要核实

操作者回复登记完成后，首次自动只读调用没有通过本地文件检查。仅检查元数据发现：专用目录仍使用继承权限，凭据文件没有生成。现有证据不能唯一确定首次失败阶段，也不能据此认定是操作者输错密码。受控复现表明，目录创建后的权限设置失败可以留下同样状态；单纯密码验证失败则应发生在目录权限已经收紧之后。

这次暴露了完整流程与单个函数测试的差别。补充的独立子进程场景覆盖从首次建目录、隐藏输入、远端验证到保存、准确解密读回、替换和撤回；同时修正了 PowerShell 字符串空值绑定影响原子替换，以及仅比较长度不足以核对保存内容的问题。

新版登记窗口仅在保存值准确读回后明确显示成功，失败显示有限错误名称；关闭提示使用按键，不再接收可见文本。已经重新打开隐藏输入窗口，等待本人完成。本节仍将真实登记和实际自动调用记为未完成，不把操作者的完成回复或合成结果代替文件与调用证据。

## DPAPI 保护磁盘上的凭据

Windows 端采用 CurrentUser DPAPI，将保存结果绑定当前 Windows 用户与本机；专用目录和文件关闭 ACL 继承，仅保留当前用户与 SYSTEM。加载前检查所有者、ACL、路径链接和记录绑定。加密记录放在项目和 Git 工作区之外，不纳入源码同步。[Microsoft 的凭据导出说明](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/export-clixml?view=powershell-5.1)解释了 DPAPI 对用户与计算机的绑定；不能把同样的 PowerShell 凭据导出方式无条件搬到其他操作系统并宣称仍然加密。

**同一 Windows 账号运行的程序仍可调用解密。** DPAPI 的作用是保护静态存储，窄 ACL 也不能隔离同一账号下的其他进程。固定动作和审核哈希用于减少误调用范围，不能当成抵御该账号被完全控制后的权限隔离。这个边界与操作者明确授予本机自动调用能力的选择一并记录。

## 密码只经过短期内存与 SSH stdin

实际调用使用独立进程的重定向 stdin：从 SecureString 临时取得字符、编码为 UTF-8 字节、发送一个换行后关闭输入，随即清零字符数组、字节数组和非托管明文缓冲区。密码不拼进命令参数，不放进环境变量，也不写明文临时文件。

SSH 保持主机密钥检查，关闭代理转发和额外端口转发；使用无伪终端的非交互通道，避免密码被终端回显。SSH 认证与 sudo 认证分别处理，现有 SSH 登录并不代表已经拥有 root。[OpenSSH 手册](https://man.openbsd.org/ssh)说明了主机验证、远程命令、代理转发及伪终端行为。

每次 sudo 调用都忽略旧时间戳，使用本次输入验证，且不刷新后续免输密码的缓存。[sudo 官方手册](https://github.com/sudo-project/sudo/blob/main/docs/sudo.man.in)对标准输入读取密码和忽略缓存的语义有明确说明。远端实际动作及其子进程不再读取这条输入，避免把残留输入交给部署脚本。

## 远端只执行有限的审核动作

工具提供只读状态检查、已发布版本复核和受审项目发布等有限入口，不提供任意 shell 命令文本。目标主机、远端身份、允许的发布目录形状和入口名称均受约束；执行前同时核对文件类型、所有者、权限、大小与预先审核的 SHA-256。

还需要防止检查与执行之间发生替换：远端读取入口一次，核对这份字节的哈希，再把**同一份字节快照**放入 root 私有临时目录执行。不能先检查某个路径，随后再次从可写暂存路径加载另一份内容。子进程使用固定解释器、清理后的环境和关闭的输入；已有发布器继续负责候选校验、版本切换、健康检查与回退。

本轮没有修改 sudoers，也没有为账号添加通用 NOPASSWD 规则。保存凭据不会跳过已有发布检查，后续新发布仍需先完成来源固定、审查、测试与文件核验。

## 结果未知时先核对现场

工具只显示有限格式的阶段结果，隐藏未审核的原始 stdout、stderr 和异常细节。密码失败、权限不符和文件审核失败各自停止，不通过重复初始化来“修复”问题。

SSH 断开或本地等待超时，表示客户端没有拿到可靠完成结果；远端动作可能已经继续执行。因此这种情况记录为“结果未知，未自动重试”。先核对当前版本、服务和发布收据，再决定是否需要恢复或重复执行。健康检查通过也不能代替用户登录和真实业务验收。

操作者可使用“忘记凭据”入口删除本地加密记录，撤回这个工具后续加载该记录的能力。它不更改服务器密码、不撤销 SSH 密钥，也不能终止已经启动的远端动作；这些操作有各自独立的控制范围。
