# 从项目入口到桌面 OS：体验与开机解锁

记录日期：2026-10-19。本章记录新一轮**本地候选的实现路线**。新的桌面外观、实时窗口总览和原生认证界面尚未完成合并公网发布；已有生产验收继续以 [README](../README.md) 和[钥匙串与多桌面](08-keychain-and-spaces.md)为准。

示例中的 `os.example.com`、`auth.os.example.com`、`EDGE_V4` 和 `CORE_V6` 均为占位名称，不对应实际部署。本仓库公开的是方法与脱敏记录，不包含可直接执行的完整发行包。

## 先确定“像 OS”的验收对象

用户期待的是打开应用、切换工作、找到文件、锁定后安全离开的连续体验。透明背景只解决其中一小部分。因此本轮把菜单、Dock、窗口、调度中心、文件和身份入口一起整理，每个可见操作都应对应真实状态或明确的不可用状态。

当前视觉参考按记录日重新核实到 **macOS 27 Golden Gate / 27.0.1**，依据为 [Apple 产品页](https://www.apple.com/os/macos/)和[安全发布页](https://support.apple.com/en-us/100100)。材质遵循导航层与内容层分工，动效用来表达打开、收起、排列和焦点变化，并提供减少动态效果与透明度的选择；参考 [Materials](https://developer.apple.com/design/human-interface-guidelines/materials) 与 [Motion](https://developer.apple.com/design/human-interface-guidelines/motion)。浏览器中的实现仍需要自己的性能和可读性验收。

| 优先项 | 候选实现方向 | 必须实际检查的行为 |
| --- | --- | --- |
| 开机与解锁 | 时钟、头像、密码与动态码阶段；公网使用原生身份页面 | 小屏高度可容纳表单，失败信息可读，键盘和自动填充正常 |
| 菜单栏 | 命令随活动应用变化，不可用操作禁用 | 点击和快捷键执行同一个命令；嵌入应用取焦后菜单不会悬留 |
| Dock | 指针距离连续放大、运行标记、恢复已有窗口 | 反复点击不会意外制造重复会话或把活动窗口藏起；触屏仍能启动 |
| 窗口 | 拖动、缩放、最小化、恢复、边缘平铺和焦点层级 | 过渡结束后仍是原业务窗口；浏览器视口变化后能找回窗口 |
| 调度中心与 Spaces | 同一批已挂载窗口参与总览；候选桌面上限扩到 16 | 选择、键盘退出、移窗和删除桌面的窗口迁移；公网完整容量另验 |
| Finder | 真实授权目录、历史、路径、搜索、排序和快速查看 | 未保存内容受保护；列表、图标和触屏入口都能完成实际文件操作 |
| Spotlight | 应用、已开窗口、根目录文件、已知节点和任务 | 结果打开正确对象，文件走 Finder 原有授权与未保存检查 |
| 外观与无障碍 | 浅深色、图标外观、玻璃染色、Dock 放大和减少效果偏好 | 偏好恢复、文字对比度、键盘焦点与低动画模式；不是只检查截图 |

此前的网页 macOS 项目适合研究交互模型。[Renovamen/playground-macos](https://github.com/Renovamen/playground-macos) 与 [PuruVJ/macos-web](https://github.com/PuruVJ/macos-web) 都提供 MIT 许可，可参考邻域 Dock 放大和窗口状态组织；它们的既有版本与本轮官方基线不同，不能直接作为“最新版全部功能”的证明。本轮桌面组件自行实现，没有复制这两个项目的代码或 Apple 专有素材；开源代码许可证也不自动授予其中第三方壁纸、字体和声音的使用权。

## 解锁页为何要维护一个原生前端补丁

最初容易设想：给 Authelia 配一个资源目录，再放入自定义 CSS 就能得到完整的开机界面。但固定版本的 [`asset_path` 文档](https://github.com/authelia/authelia/blob/v4.39.28/docs/content/reference/guides/server-asset-overrides.md)列明的是图标、标志和翻译覆盖，没有任意 HTML/CSS 替换接口。把没有这种能力的配置反复写入，无法形成可靠的定制方案。

本轮采用同一上游版本的原生前端小补丁：仅调整登录布局、样式、装饰时钟和同源背景资源，保留原来的登录与动态码组件、请求和错误处理。前端重新构建后嵌入自定义二进制，密码和动态码仍直接交给认证来源；桌面 BFF 不增加一个代收密码的代理表单。

这个制品应当作为独立维护对象，具备四项材料：

1. 固定的上游版本、可重放的修改补丁及构建输入说明。
2. 独立的自定义版本标识，明确它不是上游官方发布制品。
3. 来源收据与制品一致性检查，以及原登录、OTP、前端构建和版本输出的校验结果。
4. 随附上游完整许可证和修改说明，按 [Authelia 的 Apache-2.0 许可](https://github.com/authelia/authelia/blob/v4.39.28/LICENSE)处理分发；原官方二进制保留供回退。

单独的页面预览、前端测试和编译成功分别只能证明对应环节。本地看起来正确，仍需在真实认证流程中验证密码、动态码、错误、恢复和退出。后续升级上游时，也必须重新审查和重放补丁，不能把旧构建的来源收据沿用给新制品。

## 一次认证进入桌面，保留 MFA 与授权码流程

个人桌面与身份服务由同一人控制时，可以只为这个明确受信任的第一方 OIDC 客户端设置 `consent_mode: implicit`，省去每次进入桌面重复询问资料授权的页面。它控制的是**同意页面策略**；认证仍要求 `two_factor`，登录流程仍使用授权码和 PKCE S256。其他客户端继续保留各自策略。配置语义见[固定版本客户端文档](https://github.com/authelia/authelia/blob/v4.39.28/docs/content/configuration/identity-providers/openid-connect/clients.md)。

下面只展示相关字段之间的关系，不能代替完整配置；客户端凭据、签名、存储、会话与通知仍需独立正确配置。

```yaml
client_id: 'personal-desktop'
authorization_policy: 'two_factor'
consent_mode: 'implicit'
grant_types: ['authorization_code']
response_types: ['code']
require_pkce: true
pkce_challenge_method: 'S256'
redirect_uris: ['https://os.example.com/auth/oidc/callback']
scopes: ['openid', 'profile', 'email']
```

BFF 仍检查精确回调、状态、令牌与 owner 身份，项目窗口仍经已有钥匙串和应用授权边界。不要为了去掉一张同意页而扩大 scope、修改用户标识、降低认证等级，或把该策略批量套给其他客户端。

入口需要同时处理两种状态：首次请求根 HTML 时没有工作区会话，服务端直接跳到固定的同源 OIDC 登录入口；已经加载的 SPA 发现工作区会话失效时，也自动前往同一个固定入口。后者不使用任意返回地址或浏览器输入拼接登录 URL，且不把认证错误、API 响应和静态资源一概重定向为登录页面。

## 自动继续与主动锁定不能互相竞态

自动继续登录会带来一个细节：用户点了锁定，工作区会话先撤销，但身份服务的退出导航尚未完成。此时 SPA 若立即把“未登录”解释成“应该重新登录”，仍有效的上游 SSO 可能把桌面又带回来。

候选使用一个共享的退出锁存状态，把重复点击、会话更新和退出导航串成一次操作：

- 开始锁定时先设置锁存，只提交一次撤销请求。
- 工作区确认撤销后，更新本地状态，再前往已校验的身份退出地址。
- 已经撤销后，即使退出导航失败，也保持禁止自动重登，向用户提供明确的退出状态。
- 若撤销本身失败，才解除锁存并保留重试机会；不能把尚未成功的撤销显示为完成。

自动登录条件因此同时检查生产 OIDC 模式、会话状态、预览状态和“正在退出”状态。已有生产版本锁定关闭连接的证据继续保留；新候选的完整退出、重登和失效流程仍要重新实测，不能由这个状态模型推导成全部通过。

## 实时总览使用同一业务窗口

跨来源 iframe 通常不能由父页面直接读取画面，早期用统一卡片示意窗口的做法也无法体现真实工作内容。新候选的 LiveOverview 把**原来已挂载的窗口节点**缩放并排列到总览位置，维持原窗口 key、内容和挂载层级；选择后恢复其正常几何和焦点。最小化窗口在总览中也可参与选择。

进入总览时，业务内容暂时不可交互，由总览的选择按钮和键盘焦点负责切换；退出时恢复焦点。它不创建第二份 iframe，也不把截图或装饰卡片冒充实时业务。需要分别验证 DOM 挂载连续性、实际页面状态和网络连接连续性；“实现采用相同节点”本身还不是所有浏览器与所有应用的长期连接证明。

## Finder、Spotlight 与 Appearance 的真实范围

Finder 延用现有受保护文件 API 和授权目录，增加左侧位置、前后历史、面包屑、列表/图标视图、当前目录搜索与排序、底部状态。单击选择，双击或 Enter 打开，Space 使用安全的纯文本快速查看；二进制文件提供元信息与下载入口，文本不通过 HTML 注入渲染。触屏另有可点击的打开入口。

文件编辑、保存、上传、下载和目录扫描沿用已有能力。切换目录、打开其他文件或关闭编辑器前，未保存内容需要确认；上传覆盖已有文件也需确认。后端尚无重命名、移动、回收站和批量删除接口，候选不放置会假装成功的对应按钮。这里仍不是系统全盘或其他节点目录的 Finder。

Spotlight 聚合已注册应用、打开的窗口、已知节点与任务，以及工作空间根目录文件。文件结果把已有 API 返回的条目交给 Finder，同样经过导航、授权和未保存检查；取消打开也结束这次请求，避免重复消费。当前目录搜索与根目录结果都不等同于全盘递归索引，网页快捷键也可能被操作系统或浏览器截获。

Appearance 调整桌面自己的主题、图标、玻璃染色、Dock 放大以及减少动态与透明度偏好，并恢复有效的已保存偏好。它使用浏览器 CSS 和合成能力，不能据此承诺 Apple 原生材质的光学效果，也不修改宿主系统设置。原生 `.app`、内核、驱动、Continuity、AirDrop、Apple Intelligence、多屏系统手势、完整舞台管理与窗口专属全屏 Space 都不因这些控件而出现。

## 把发布合并为一次执行，保留独立回退

网络拓扑继续由 `EDGE_V4` 接收公网 IPv4，`CORE_V6` 接收公网 IPv6，二者通向同一身份与项目策略。本轮体验升级不应夹带 DNS、证书、防火墙、应用白名单、原站密钥或节点服务的额外修改。

发布前完成构建、来源审查、清单固定和候选检查，再由操作者执行一个合并入口。该入口的阶段应当清楚、可重试，并只输出固定的分类结果：

| 阶段 | 应做的检查或动作 | 失败时的处理 |
| --- | --- | --- |
| 核验输入 | 清单、文件集合、来源收据、权限、二进制版本与不可变发行目录一致 | 在选择版本或重启前停止 |
| 验证候选 | BFF 使用现有受管环境与凭据视图；认证配置只给唯一目标客户端增加同意策略并通过原生校验 | 不重新收集密码、Token 或绑定验证器，不改运行中身份 |
| 保存基线 | 保存旧版本选择、认证配置和独立启动覆盖；保护已有钥匙串与应用路由 | 不能证明基线一致时停止，避免覆盖回退材料 |
| 激活 | 原子选择发行版、更新限定配置与启动覆盖，再按顺序重启和检查 | 任一步失败，分别尝试恢复版本、配置、启动覆盖与服务健康 |
| 验收与重跑 | 核对身份健康、BFF、匿名项目拒绝与可信 TLS 认证跳转；已精确激活时只验证 | 健康检查不能代替本人 MFA、业务和外网双栈验收 |

一个现场易漏的细节是 systemd 凭据的可见性：服务自己的挂载视图与宿主视图可能不同。候选校验应固定核对正在运行的服务进程身份，并进入其已固定的 mount namespace 后再降权运行；不能仅因宿主路径不可读，就复制密钥、放宽权限或跳过检查。依据见 [systemd 执行环境与凭据](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html#Credentials)和 [nsenter mount 参数](https://man7.org/linux/man-pages/man1/nsenter.1.html)。

回退步骤需要分别执行并汇总失败，不能因为第一次恢复失败就放弃其余恢复。已有快照与目标清单不一致时应拒绝续跑；已激活的精确版本再次执行时，不应重新初始化秘密或无条件重启。合并入口减少的是操作者反复复制命令的次数，检查依据与失败阶段仍需保留。

## 当前状态与下一轮验收

本轮桌面候选已在隔离的本地环境运行，原生认证前端按固定上游源码构建和核对；**新的合并公网版本尚未部署并验收**。本章不发布私人截图、原始日志、收据哈希或真实部署输入，也不把历史版本的业务通过自动转记到候选版本。

发布后要重新完成实际密码与 Authenticator 解锁、主动锁定与重登、真实应用窗口、实时总览和文件工作流，并核对较小视口、键盘、减少效果和持续连接。外部 IPv6、SMTP 实际投递、原站自动下载弹窗，以及既有路线图中的其他未完项继续保留。目标仍是一套可日常使用的集群 Web OS；“完整复刻最新 macOS”尚无对应的完成证据。
