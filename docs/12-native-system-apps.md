# 从窗口布局到原生系统应用

这一阶段的重点是让项目在同一套桌面行为里工作。原站适合完整管理的应用，继续保留其原生页面与业务协议；集群设备、资源和实例列表则可以有 OS 自己的窗口。两者都必须使用同一个已解锁的主人会话，不能把“画出一个界面”当成数据已经接通。

## 窗口是一份可还原的状态

浮动位置与尺寸应该独立于排列模式。选择左半、右半、四个角或填充时，只修改模式；还原时使用原先的矩形，最小化与多桌面切换也不覆盖它。短屏无法容纳最低高度的四分窗口时降级成半屏；视口变小后，持久化的下半屏窗口也要重新约束。

本次真实拖动标题栏到边缘后，出现布局预览并完成吸附；恢复后回到原尺寸。项目 iframe 的身份不因排列而重建。窗口自身容器允许裁切正文，但布局菜单必须挂到桌面层并受视口限制，否则四分窗口会把菜单截掉。

还有一个容易忽略的故障：悬停绿灯开启菜单通常有延迟。如果窗口在计时结束前关闭、最小化或移到另一桌面，旧计时器可能打开一个看不见的菜单，并持续阻断原生项目输入。解决方式是到期时再次检查窗口可见性，失效立即关闭，完成布局后把键盘焦点还给绿灯。

## 材料与运动服务于操作

菜单、Dock、标题栏和正文应有不同材料层。正文保持清晰的承载面，控制层再使用透射、模糊、边缘高光与阴影。深色墙纸配浅色外观时，菜单栏不能沿用最低透明度；暗色菜单中的原生选择框也需要显式文字与边界颜色。

程序坞的连续放大使用一个动画帧循环与阻尼运动，不为每次指针移动触发 React 渲染。应用的“减少动态效果”和系统偏好共同生效；减弱模式下，放大、抬升与水平位移都归零。窗口内布局使用容器宽度适配，而非只看整个浏览器宽度，因为半屏窗口和全屏浏览器经常同时存在。

参考依据为 Apple 当前 [macOS 产品说明](https://www.apple.com/os/macos/)、[材料指南](https://developer.apple.com/design/human-interface-guidelines/materials)与[窗口指南](https://developer.apple.com/design/human-interface-guidelines/windows)。CSS 是网页中的实现路径，不代表复现了原生合成器的全部光学与系统能力。

## 原生项目的数据边界

| 原生窗口 | 真实来源 | 本阶段功能 |
| --- | --- | --- |
| 活动监视器 | 现有受保护的主机资源与节点采样 | 核心资源、节点列表和搜索；远端未采集资源显示未知 |
| Tailscale | 核心节点的固定状态命令 | 设备、地址与在线状态筛选；在线不等于每个服务可用 |
| 隧道客户端 | 固定服务管理器只读属性 | 加载、运行、子状态和开机启动；不把进程状态等同隧道连通 |
| Minecraft | 现有 MCS 管理 API | 明确登记为 Java 或基岩版的实例；终端、文件、电源操作接续 MCS 原生管理窗口 |

Minecraft API 通过服务端钥匙串取用既有凭据，只放进上游请求头，不放 URL。接口不能接受任意命令、来源地址或实例配置。返回值只投影需要的名称、状态、版本和玩家数，丢弃启动命令、环境、远控口令与原始配置。

接口既要验证请求身份，也要验证活动的主人租约：调用前、取回凭据后、收到响应后都检查；锁定时中断在途请求。分页、节点数、响应字节与总时限均有上限。部分节点离线或失败要明确显示，不能用空列表假装完整读取。预览窗口不请求生产服务，也不展示伪造的项目状态。

## 实际验收与尚未完成

这一阶段完整测试为 210 项通过、0 失败，Windows 的 13 项 POSIX 权限用例明确跳过；发布器另在 Linux 跑过 17 项检查。渲染验收覆盖真实拖动吸附、四分布局、还原矩形、布局菜单不裁切、焦点、暗/浅色、Dock 恢复和减弱动效。

自动 SSH 发布后再次独立检查当前版本与三服务。既有身份会话自动返回桌面，无需重新索取密码或动态码；公网四个新增窗口取得真实数据，Minecraft 沿用现有钥匙串。原项目管理、完整锁定生命周期、外部 IPv6、SMTP 投递与恢复演练仍按各自证据记录。

Beszel、远程桌面、学习站、开发控制台、路由器及智能体各有不同的身份和通信协议。不能为了让窗口“打开成功”而统一删除安全头、启用任意可信身份头、导出原生密钥，或直接启动原本停用的智能体。下一阶段按实际版本和原生协议逐个完成管理员接入。
